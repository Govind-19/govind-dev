built a dashboard for schools this week. claude helped.... beautiful graphs, clean cards, everything rendering nicely 😮‍💨

i was happy. it looked done.

took it to my lead and he asked one thing....

<Pull>"why is this one page hitting the backend so many times?"</Pull>

and i opened the network tab 🥲

every graph was making its OWN api call. one dashboard, one page load, and the server getting hit again and again for data we could have pulled in a single call.

it looked fast on my screen. thats the trap. my screen is one browser sitting next to the server on my own machine. but every school opening that dashboard was quietly hammering the backend, all day, every day.

<Ex>Ex: 8 graphs = 8 calls felt completely normal to me. but 8 calls per page load × every school × every day.... thats the part i wasnt seeing 🤷‍♂️</Ex>

the fix was simple once i could see it. one endpoint, one response, all the dashboard data together. the frontend just splits it into the graphs.

and this is the second time in two days i've learned the same lesson from a different direction — [pagination was the exact same shape](/journal/pagination-is-a-contract-not-a-frontend-feature). the screen looked right, the work under the screen was wrong.

claude built exactly what i asked. i asked for graphs, it gave me graphs. it didnt think about the number of backend calls because i didnt either.

<Pull>a dashboard isnt a pile of graphs. its one screen asking the server one question.</Pull>

the scope i miss is always the scope thats under the screen.
